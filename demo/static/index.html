MCP Tool & Skill Developer · working example

Governed MCP tools and skills for AI agents, running live on Azure and AWS.

Beast Assist is a small version of an enterprise agent platform: MCP servers in Python and FastAPI, SKILL.md skills with a registry, OPA authorization, Entra ID tokens through Azure API Management, a LangGraph coordinator on Amazon Bedrock, and RAG on PostgreSQL + pgvector. Everything on this page is live: the buttons below make real calls through every one of those layers.

    Live console

    Each button sends one real MCP call. This page asks its own backend (an Azure Container App) to get an Entra ID token and call Azure API Management, which forwards to the MCP server, which asks OPA. The trace shows every hop, the exact JSON-RPC sent, and who answered.

    Ask the agent

    The LangGraph coordinator from the repo, running in Azure, with its model on Amazon Bedrock. It resolves a skill from the registry, loads only that skill's tools over MCP, and follows the skill's workflow. Its token is read-only, so write tools are refused. Limited to a few questions an hour.

    What is not in the cloud: the two systems the tools wrap, the Scarlet Beast agile board and Scarlet College, which are existing Scarlet Beast web apps on their own server. They play the part Jira and Confluence play for SmartAssist: systems of record behind the MCP servers, reached over HTTPS. The platform itself (the MCP servers, policy, registry, database, gateway, identity, agent, and this page) runs in Azure, and the model runs in AWS.

    What was built, against the job description

    The role asks forBeast Assist has
    MCP servers in Python/FastAPI, one backend each, tools auto-discoveredagile-mcp and college-mcp on the MCP Python SDK 2.2, generated from mcp-template/; tools are files in src/tools/ found at startup
    Tool design for LLMsbootstrap_guide first, slim rows, input checked before the backend, errors as code: message. Next: hint
    SKILL.md: allowed_tools, inputs, lifecycle, workflow3 skills (board-standup, college-tutor, study-plan-from-job) with validate, audit and upload scripts
    Skills Registry on PostgreSQLFastAPI registry: list, resolve by alias, publish behind the Skills.Publish role; serves the OPA bundle
    Authorization with OPARego: a skill may call only its allowed_tools, its lifecycle must fit the environment, writes need Tools.Write; 6 policy tests
    Entra ID, Azure API Management4 app registrations with app roles; APIM Consumption with validate-jwt and a required skill header; servers verify the token again
    LangGraph, BedrockCoordinator graph: resolve skill → preflight → specialist ReAct agent with only that skill's tools; Bedrock Converse
    RAGScarlet College lessons chunked by heading, embedded (bge-small or Titan V2), pgvector HNSW, cited answers; hit@k and MRR eval
    Docker, Kubernetes, certificates, healthOne image; Kustomize dev/prod overlays with HPA, PDB, NetworkPolicy, cert-manager; /healthz and /readyz everywhere
    Evaluation, observability, CI13 benchmark scenarios; OpenTelemetry traces and one log line per tool call; GitHub Actions test, lint, image
